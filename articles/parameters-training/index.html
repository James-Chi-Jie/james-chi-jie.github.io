模型参数究竟是什么？一次预测错误如何变成学习？

通过两个可核算的小实验，理解模型参数、Loss、梯度、学习率与反向传播，并区分 LLM 的训练与推理。

在上一篇文章里，我们讨论了 Tokenization：一段文字会被切分成 Token，再转换成一串 Token ID。Token ID 本身只是编号，并不直接表示语义。

例如，面对「苹果是一种……」和「汽车是一种……」，模型应该给出不同的后续预测。但 Token ID 只是编号，ID 的大小和相邻关系并不代表语义。模型究竟依据什么产生不同的预测？

模型之所以能根据不同上下文产生不同预测，是输入表示与模型内部计算共同作用的结果。其中一项关键因素，就是一组参与计算、并能在训练中不断调整的数值——模型参数。这篇文章先用两个可核算的小实验，拆开看参数怎样影响预测，又怎样通过训练逐渐调整。至于 Token ID 怎样变成模型能够处理的向量，我们留到下一篇解释。

一、先分清：输入和参数不是一回事

先看一个最简单的计算模型：

\hat y=wx

它只有一个可以调整的参数：$w$。

  • $x$ 是输入。每来一条新样本，输入值都可能不同。
  • $w$ 是参数。它属于模型，会被多条样本共同使用，并在训练过程中调整。

在同一次计算中，所有样本使用的是同一个 $w$，所以它确实是一个共享数值；但它不是永远不变的常量。每完成一次训练更新，模型都可能得到一个新的 $w$。

这里的 $w$ 只是一个最简单的标量参数。真实神经网络通常有大量参数，它们可以组织成向量、矩阵等形式；权重、偏置，以及 Embedding 表中的数值，都可能是模型参数。为了先看清参数如何影响计算，这个例子暂时只保留 $w$，省略偏置项。

假设我们准备了三条训练数据：

样本 输入 x 目标结果 y
A 2 6
B 3 9
C 4 12

这里的输入和目标结果是实验设计者手工构造的。它们恰好符合 $y=3x$，但训练程序并没有被告知正确参数是 3；程序只拿到了三组输入与目标结果。

注意，这里的 $x$ 是为了演示计算而设计的数值特征，不是把 Token ID 直接当成可以做加减乘的连续数值。Token ID 如何变成模型实际处理的向量，留到下一篇再展开。

现在让模型从 $w=0$ 开始：

样本 输入 x 目标结果 y 当前预测
A 2 6 0
B 3 9 0
C 4 12 0

三个预测结果都是 0，显然不符合目标。模型怎样知道自己预测得有多差？又该怎样调整 $w$？

二、预测错了，怎样衡量？

我们先需要一个标准，把预测结果和目标结果之间的差异变成一个可以计算的数值。

在这个实验里，我们使用均方误差（Mean Squared Error，MSE）：

Loss=\frac{(\hat y_1-y_1)^2+(\hat y_2-y_2)^2+(\hat y_3-y_3)^2}{3}

把刚才的三个预测代进去：

Loss=\frac{(0-6)^2+(0-9)^2+(0-12)^2}{3}=87

这个 87，就是模型在当前参数 $w=0$ 下的 Loss。

可以先把它理解为：当前这组参数产生的预测，整体上要付出多大的错误代价。

接下来，如果模型调整了参数，我们就可以重新计算预测和 Loss，看看结果有没有改善。

这里要注意：Loss 只告诉我们当前预测表现如何。单看 87 这个数字，并不能直接知道 $w$ 应该增大还是减小。我们还需要另一个信息。

三、怎样知道参数应该往哪边调整？

假设现在的参数是 $w=0$，我们想知道：如果把它稍微调大一点，Loss 会怎样变化？

可以尝试几个不同的 $w$，观察 Loss。如果 $w$ 稍微增加，Loss 下降，说明当前方向有帮助；如果 Loss 上升，说明当前方向不合适。

在实际模型中，参数可能有成千上万甚至更多。逐个尝试不同参数组合，成本太高。因此，我们需要一种方法，直接计算 Loss 在当前参数位置附近，对参数变化有多敏感。

这个信息叫作梯度（Gradient）。

在只有一个参数的当前实验里，梯度就是 Loss 对 $w$ 的变化率。它的正负可以告诉我们局部应该往哪个方向调整：

  • 梯度为负：在当前位置附近，增大 $w$ 会让 Loss 下降。
  • 梯度为正：在当前位置附近，减小 $w$ 会让 Loss 下降。

当 $w=0$ 时，我们计算得到的梯度是 -58。这个数字不是凭感觉判断出来的，而是把三条样本对 Loss 的影响合在一起计算：

\frac{\partial Loss}{\partial w}=\frac{1}{3}\sum_{i=1}^{3}2(wx_i-y_i)x_i

代入当前的 $w=0$：

\frac{2(0-6)\times2+2(0-9)\times3+2(0-12)\times4}{3}=-58

这说明在当前位置附近，增大 $w$ 会让 Loss 下降。

但应该增大多少？

这就轮到学习率（Learning Rate）了。它控制每次参数更新的步长。

最简单的梯度下降更新公式是：

w_{\text{new}}=w_{\text{old}}-\eta\frac{\partial Loss}{\partial w}

其中 $\eta$ 就是学习率。它控制每次参数更新的步长。学习率不是模型从训练样本中学出来的参数，而是训练过程设置和调整的超参数；实际训练中也可能按预先设定的策略动态变化。假设学习率取 0.01：

w_{\text{new}}=0-0.01\times(-58)=0.58

于是，参数从 0 变成了 0.58。再用新参数重新预测：

样本 输入 x 目标结果 y 新预测
A 2 6 1.16
B 3 9 1.74
C 4 12 2.32

重新计算后，Loss 从 87 降到了 56.6119。

这就是一次完整的参数更新：

模型先做预测，再计算 Loss；根据梯度确定调整方向，学习率决定调整步长；参数变化后，再用新参数进行预测。

参数更新闭环：Loss 衡量当前预测，梯度给出局部调整方向，学习率决定步长；参数更新后再重新预测。

四、为什么不是每次更新都一定变好？

刚才我们使用的学习率是 0.01。如果学习率换成其他数值，会发生什么？

我们实际运行了三组对照：

学习率 训练 Step 最终参数 w 最终 Loss 结果
0.01 100 约 3.000000 小于 1e-10 逐步收敛
0.05 20 约 3.000000 小于 1e-10 更快收敛
0.12 20 约 -770.748605 约 5,787,306.73 发散

为什么学习率太大，反而会出问题？

梯度告诉我们当前位置附近应该往哪个方向走，但它描述的是当前位置附近的变化趋势，并不保证走得越远越好。

在学习率为 0.12 时，第一次更新就把 $w$ 从 0 推到了 6.96，Loss 不但没有下降，反而从 87 增加到了 151.5888。后续更新继续越过合适的位置，最终发散。

所以，学习率不是越大越好，也不是越小越好。它需要结合模型、数据和优化过程选择。

还有一个细节：上面的每一步更新，都使用了三条训练样本共同计算 Loss 和梯度。这样的方式叫作全批次梯度下降（Full-batch Gradient Descent）。真实训练中，通常会把数据分成批次来计算和更新，而不是每次都把全部训练数据放进来。

到这里，我们已经看到：即使模型只有一个参数，也可以通过反复预测、计算 Loss 和更新参数，逐渐学到训练数据中的规律。

但一个参数能表达的关系毕竟有限。如果输入里有不止一种信息，模型是不是需要更多参数？

五、增加参数，模型就能区分更多输入吗？

这次我们把输入扩展成两个数值特征：$x_1$ 和 $x_2$。

它们只是实验中人为提供的两个独立输入维度，不代表真实苹果、汽车的语义特征。

训练数据如下：

样本 x1 x2 目标结果 y
A 1 0 2
B 0 1 3
C 1 1 5

我们先看一个受限的模型：

\hat y=w(x_1+x_2)

它先把两个输入相加，再乘以同一个参数 $w$。

于是：

  • 样本 A 的输入是 (1, 0)，相加得到 1。
  • 样本 B 的输入是 (0, 1)，相加也得到 1。
  • 样本 C 的输入是 (1, 1)，相加得到 2。

问题出现了：A 和 B 原本是两种不同的输入，但在进入参数计算之前，就已经被合并成了相同的数值。

因此，无论 $w$ 怎么调整，A 和 B 都只能得到相同的预测。

我们用全批次 MSE、学习率 0.2 训练 40 Step 后，模型收敛到 $w\approx2.5$：

样本 预测结果 目标结果
A 2.5 2
B 2.5 3
C 5 5

模型已经把 Loss 降到了它所能达到的最低点，约为 0.1667，但 A 和 B 仍然不能同时预测正确。

这不是训练次数不够，而是模型的计算方式限制了它：两个输入维度被提前合并，模型无法分别调整它们的影响。

现在，我们改变一下模型：

\hat y=w_1x_1+w_2x_2

不再让两个输入共用同一个权重，而是让它们分别拥有可以学习的参数：

  • $w_1$ 负责调节 $x_1$ 对结果的影响。
  • $w_2$ 负责调节 $x_2$ 对结果的影响。

训练开始时，两个参数都是 0。我们仍使用全批次 MSE 和 0.2 的学习率，每一步都用三条样本共同计算梯度，再分别更新两个参数：

Step w1 w2 Loss
0 0 0 12.6667
1 0.9333 1.0667 4.6252
5 2.0501 2.5611 0.1154
10 2.1044 2.8653 0.0100
40 2.0016 2.9984 约 0.00000178
120 2.0000 3.0000 约 2.02e-16

最后，两个参数分别接近 2 和 3：

w_1\approx2,\quad w_2\approx3

再代回三个样本：

  • A：$2\times1+3\times0=2$
  • B：$2\times0+3\times1=3$
  • C：$2\times1+3\times1=5$

三个预测都接近目标结果，Loss 也接近 0。

注意，表格中的 Step 只是展示各自的收敛过程：共享权重模型训练 40 Step，独立权重模型训练 120 Step。这不是训练速度对比；我们真正要比较的是，两种计算结构能否表达不同的输入—输出关系。

这两个模型都是刻意简化的线性模型，没有隐藏层或非线性激活。我们只改变输入与权重的连接方式，是为了单独看清参数自由度的作用；它们并不是完整神经网络，更不是 LLM 的结构复刻。

这里有一个重要的区别：这次实验改变的不只是参数数量，还改变了参数与输入之间的连接方式。两个独立参数让模型有了分别处理两个输入维度的自由度。

但这不代表参数越多，模型效果就一定越好。

共享权重会合并不同输入维度的影响；独立权重允许模型分别调整各维度的作用。

如果两个不同样本提供给模型的完整输入完全相同，那么在相同参数和确定性计算下，模型也只能得到相同的预测。即使增加更多参数，也不能凭空知道两个样本其实是不同对象。

例如，两个样本的输入都是 (1, 0)，但目标结果分别是 2 和 3。模型没有任何输入信息可以判断当前面对的是哪一个样本，因此无法同时给出两个不同结果。即使把共同预测调到最合适的 2.5，这两条样本的平均 MSE 仍然是 0.25，而不是 0。如果后续使用随机采样，最终选出的 Token 可能因随机性不同，但模型给出的概率分布仍然相同；这不是模型从输入中识别出了两个对象的差异。

还有一种情况：如果 $x_1$ 和 $x_2$ 在所有训练样本中始终相等，那么模型也无法从这些数据中分别识别两个权重的作用。因为：

w_1x_1+w_2x_2=(w_1+w_2)x_1

这时，数据实际上只能约束 $w_1+w_2$ 的总和，无法判断这两个参数各自应该是多少。这也解释了为什么我们不能只看模型有多少参数，还要看输入数据提供了什么信息，以及模型结构能否利用这些信息。

输入特征提供样本的信息，参数决定模型如何处理这些信息；参数数量和连接方式，则影响模型能够表达多复杂的映射。

六、反向传播：一个 Loss 怎样影响前面的参数？

到目前为止，我们已经用过好几次梯度：实验一算出了 $-58$，实验二让两个参数分别根据自己的梯度更新。

但是，这里还有一个尚未回答的问题：Loss 是最后才算出来的，模型怎么知道更早参与计算的参数应该怎样变化？

先回到实验一。为了看清计算过程，我们暂时只取第一条样本：输入 $x=2$、目标 $y=6$、参数 $w=0$。

模型先从输入走向输出：

x=2,\quad \hat y=wx=0,\quad \ell=(\hat y-6)^2=36

这叫作前向计算：用当前参数产生预测，再得到这条样本的损失。

现在我们已经知道损失是 36，但单看这个数字，仍然不知道怎样调整 $w$。因为 $w$ 并不直接出现在损失的最后一步里；它是先影响预测值 $\hat y$，再间接影响损失。

因此，我们可以反过来沿着这条计算关系求变化率。

首先，假设预测值 $\hat y$ 发生一点变化，损失会如何变化？

\frac{\partial \ell}{\partial \hat y} =2(\hat y-y)=2(0-6)=-12

然后再问：参数 $w$ 发生一点变化，预测值又会变化多少？

\frac{\partial \hat y}{\partial w}=x=2

把这两个关系接起来，就知道参数 $w$ 对损失的影响：

\frac{\partial \ell}{\partial w} =\frac{\partial \ell}{\partial \hat y} \times\frac{\partial \hat y}{\partial w} =(-12)\times2=-24

这里用到的，就是微积分里的链式法则：当一个量通过中间结果影响另一个量时，可以把每一段的局部变化率连接起来。

其余两条样本也沿相同的计算关系求导，分别得到 $-54$ 和 $-96$。三条样本的平均梯度为：

\frac{-24-54-96}{3}=-58

这正是实验一第一次更新参数时用到的梯度。

你可以把刚才的计算理解成两条方向相反的信息流：

  • 前向：输入和参数 → 预测值 → Loss。
  • 反向：从 Loss 出发，利用各步的局部导数，逐步算出 Loss 对前面参数的梯度。

为什么要按照这个方向算？因为只有先得到最终的 Loss，才能知道我们究竟要衡量哪一个结果的变化；而模型的前面可能有很多层，每层都通过中间结果间接影响它。

真实神经网络的计算路径会更长。假设某个参数 w₁ 先影响中间结果 h，这个中间结果再影响预测值 ŷ，而预测值最后决定 Loss。在标量形式的简化示意里：

\frac{\partial Loss}{\partial w_1} = \frac{\partial Loss}{\partial \hat y} \times \frac{\partial \hat y}{\partial h} \times \frac{\partial h}{\partial w_1}

反向传播沿计算路径反向连接局部变化率，计算 Loss 对参数的梯度；参数更新由优化器完成。

层数越多，就需要沿着更多计算关系继续传递。实际神经网络还涉及向量、矩阵和分支，梯度在分支处也需要汇总。**反向传播（Backpropagation）**就是沿计算图高效地反向应用链式法则，并复用中间梯度，计算出各个可学习参数的梯度。

注意，反向传播还没有改变任何参数。它的输出是各个参数的梯度；接下来才由优化器利用这些梯度和学习率等信息更新参数。然后模型才能用更新后的参数重新前向预测。

我们的两个 Python 实验直接手写了梯度公式，并没有实现通用的自动求导引擎。它们验证了梯度和参数更新，但不能因此声称已经训练了一套多层神经网络。这里使用实验一的手算，是为了把反向传播背后的链式关系看清楚。

七、回到 LLM：模型怎样学习预测下一个 Token？

前面两个实验使用的都是非常简单的线性模型。

实验一用一个参数学习 $x$ 和 $y$ 之间的关系；实验二用两个独立参数分别处理两个输入特征。

真实的 LLM 要处理的输入远比这复杂。它接收的是 Token 序列，内部有大量参数，经过多层计算后，需要预测词表中下一个 Token。

不过，训练的基本逻辑并没有改变：

先预测，再和已知目标比较，计算 Loss，然后根据梯度更新参数。

以典型的自回归语言模型为例。训练数据中有一段 Token 序列。对于其中一个预测位置，模型根据当前位置之前的上下文预测下一个 Token；训练数据中真实出现的下一个 Token，则作为这一位置的目标。这里的“知道目标”是训练流程拿它来计算 Loss，并不是把未来 Token 提前提供给模型作为当前预测的输入。

模型根据当前上下文，为词表里的每个 Token 计算一个分数。这些还没有转换成概率的分数叫作 logits。概念上，经过 Softmax 转换后，就能得到各个 Token 的预测概率。

训练数据告诉我们，这个位置真实出现的下一个 Token 是什么。于是，我们可以检查模型给这个正确 Token 分配了多大的概率。

这里使用的损失函数通常是交叉熵（Cross Entropy）。不要把前面线性回归实验中的 MSE 当成 LLM 的标准训练损失：MSE 只是为了让参数更新更容易手算；自回归语言模型通常使用交叉熵来评价真实下一个 Token 在当前上下文下的预测概率。对于一个预测位置，它对应的损失可以写成：

Loss=-\ln(P(\text{正确 Token}\mid\text{当前上下文}))

假设模型给真实下一个 Token 的预测概率分别是：

正确 Token 的预测概率 对应的 Loss
0.5 约 0.693
0.9 约 0.105

可以看到，模型给正确 Token 的概率越高，这个位置对应的 Loss 就越低。真实训练会在大量样本的多个预测位置上计算这样的损失，再汇总成训练目标。

交叉熵根据真实目标 Token 的预测概率，衡量当前预测的损失。

有了上一节的反向传播，我们就能把这次交叉熵 Loss 沿着实际模型的计算图往回求导，得到各个参数的梯度。**优化器（Optimizer）**随后根据梯度和学习率等设置更新参数。

前面的实验使用 MSE，语言模型主要使用下一 Token 的交叉熵；损失函数虽然不同，但「前向预测 → 根据目标计算 Loss → 反向计算梯度 → 优化器更新参数」的学习机制是一致的。真实 LLM 的计算图远比线性实验复杂，所以需要高效的反向传播，而不是逐个参数重新推导整条计算路径。

实际训练框架通常会直接从 logits 计算数值稳定的交叉熵，不一定先单独保存一整张概率表。

八、训练和回答问题，是同一个过程吗？

现在还剩下一个容易混淆的问题：

既然在训练阶段，模型做出预测后会计算 Loss 并更新参数，那我们平时每调用一次 LLM API，模型是不是也会学习一次？

不是。

训练和推理是两个不同的过程。

在训练阶段，模型拿到训练样本，也知道真实的下一个 Token 是什么。它可以计算 Loss、通过反向传播得到梯度，再由优化器更新参数。

而在普通推理阶段，模型拿到的是用户当前的输入。它需要根据已经训练好的参数进行计算，预测下一个 Token，并逐步生成回答。

这时没有供模型对照的真实答案，也不会因为用户问了一个问题，就自动执行一次反向传播和参数更新。

可以把两者放在一起看：

训练（Training） 推理（Inference）
输入 训练样本 用户提供的上下文
是否有已知目标 有真实的下一个 Token 通常没有
是否计算训练 Loss 是 普通生成时不需要
是否计算梯度 是 普通生成时不需要
是否更新模型参数 是 否
主要目的 从数据中学习参数 使用已有参数生成结果

训练阶段通过 Loss、反向传播和优化器更新参数；普通推理阶段使用已训练参数生成回答。

因此，我们平时调用模型 API，实际上是在使用已经训练好的参数，而不是每次提问都重新训练模型。服务端可能会记录请求、更新其他系统状态，模型提供方也可能在独立流程中继续训练或更新模型，但这些都不等于当前这次普通推理请求正在修改模型参数。

回到最初的问题

现在再回头看 Token ID。

它只是一个编号，不能直接告诉模型这个 Token 的语义。但模型拥有一套从训练数据中逐步调整出来的参数，可以利用输入信息进行计算，并通过训练过程改善预测。

参数不是一张张对应着词语和事实的卡片，也不是每个样本单独携带的信息。它们是模型内部一组可学习的数值配置，决定了模型怎样处理输入、怎样产生预测。

我们已经知道参数为什么需要学习，以及预测错误怎样转化为参数更新。

但最初的问题还没有完全解决：Token ID 只是编号，它究竟怎样变成模型能够处理的输入信息？

下一篇，我们就从 Embedding 开始，看看模型怎样通过 Token ID 找到对应的向量，以及为什么常见语言模型中的 Token Embedding 向量本身也是可学习参数。
