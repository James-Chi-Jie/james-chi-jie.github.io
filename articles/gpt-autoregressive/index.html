GPT 为什么能够逐 Token 生成回答？

从输出矩阵如何为词表候选打分出发，解释不同生成前缀如何影响下一 Token，以及训练与生成的计算节奏为何不同。

上一篇文章中，我们沿着“小明把钥匙放进书桌抽屉，后来自己去了厨房”的故事，看到 Attention 如何帮助模型从前文汇总相关信息。

现在，把完整故事和一个问题交给 GPT：

小明把钥匙放进书桌抽屉，随后去了厨房。钥匙在哪里？

我们期待它回答“书桌抽屉”。可是，输入并没有直接给出答案，屏幕上的文字也不是事先写好后逐字播放的。GPT 究竟怎样从已有前文，一步步产生回答？

一、问题和答案，究竟哪些是我们给它的？

为了观察生成过程，先把输入写成一个便于续写的形式：

小明把钥匙放进书桌抽屉，随后去了厨房。问：钥匙在哪里？答：

注意，“问：”和“答：”是我们给它的文字，真正的答案“书桌抽屉”并没有提前放进去。

故事提供了两条信息：钥匙被放进抽屉，小明后来去了厨房。我们希望模型依据与钥匙有关的线索回答，而不只是重复最后出现的地点。至于它为什么可能做对，先交代一个必要前提。

二、模型为什么可能答对没见过的题？

即使训练时没有出现过这道具体的“小明与钥匙”问答，模型也可能回答正确。因为它在大量文本的下一 Token 预测训练中，不仅可能记住局部表达，也可能学到能用于新文本的模式；这次输入又明确提供了“钥匙放进抽屉”的线索。它因此可能更倾向于续写“书桌抽屉”，而不是“厨房”。

但没见过这道题不等于从没接触过任何问答数据，一次答对也不能证明模型确实发生了泛化。预训练、后训练和泛化的验证，后续会单独研究。这篇先关注另一个问题：模型怎样把当前的预测倾向变成一个具体的 Token？

三、模型怎样决定第一个新 Token？

回到“小明把钥匙放进书桌抽屉，随后去了厨房。问：钥匙在哪里？答：”这段前文。模型已经读过故事和问题，但还没有输出答案。它怎样把内部的数值表示转换成“书桌抽屉”这个候选？

我们可以直接接上 AI03 已经算过的一步：在上一篇的二维教学实验中，询问“钥匙在哪里”时，两条线索参与 Attention 汇总，得到向量 [0.804, 0.196]。它来自“钥匙放在抽屉”这条线索与“小明去了厨房”这条线索的加权汇总，还不是中文答案。

真实 GPT 在 Attention 之后通常还有其他计算，并由最后一层的隐藏向量进入输出层。为了顺着上一篇的数字继续手算，我们暂时省略这些中间步骤，假设输出层这次接收到的二维向量就是 [0.804, 0.196]。 这是人为简化的接力计算，不是声称真实 GPT 会将那次 Attention 输出原样直接用来选词。

下一步，输出层要把这个向量转换成词表中每个候选 Token 的分数。我们仍用三个候选组成教学词表，按以下固定顺序排列：

词表中的候选 Token 书桌抽屉 厨房 。
输出矩阵中对应的列 [2, 0] [1, 0] [0, 1]

这张表就解释了接下来的矩阵：第一列负责算“书桌抽屉”的分数，第二列负责算“厨房”的分数，第三列负责算“。”的分数。每一列有两个数，是因为我们手里的上下文向量只有两个数。

把这三列放在一起，就得到一个两行三列的输出矩阵。现在让刚才从上一篇借来的向量与它相乘：

[0.8040.196]×[210001]=[1.6080.8040.196]\begin{bmatrix}0.804&0.196\end{bmatrix} \times \begin{bmatrix}2&1&0\\0&0&1\end{bmatrix} = \begin{bmatrix}1.608&0.804&0.196\end{bmatrix}[0.804​0.196​]×[20​10​01​]=[1.608​0.804​0.196​]

结果不是抽象的三个数字，而是按照同一词表顺序排列的三个候选分数：

候选 Token 书桌抽屉 厨房 。
得分（Logit） 1.608 0.804 0.196

从上一篇的教学向量出发，经输出矩阵得到三个候选分数；数值为教学示意。

例如，“书桌抽屉”的分数来自上下文向量与输出矩阵第一列的点积：0.804 × 2 + 0.196 × 0 = 1.608。另外两列也按同样方式计算。这里的 Logit 是尚未转换成概率的分数，不代表“钥匙真实位于抽屉的概率”。

如果采用最简单的选词方法——选择分数最大的候选，那么第一轮便选中“书桌抽屉”。到这里，我们就把上一篇的Attention 汇总向量，经本篇的词表输出矩阵，连接到了真正要生成的候选 Token 上。

不过，这个结果不能用来证明模型学会了找钥匙。向量和输出矩阵的数字都属于教学设定，我们特意挑选了容易计算、并能让“书桌抽屉”得分最高的一组参数。在真实 GPT 中，输出矩阵的数值由训练学习得到，而且词表与隐藏向量的规模远比这里大。向量的第一维或第二维也不天然代表“抽屉”或“厨房”；这里只是人为约定每列对应哪个候选 Token。

最后再把数值计算和文字对应起来：严格说，模型从词表分数中选出的是一个 Token ID，通过 Tokenizer 的解码关系才得到可见文字。这里把“书桌抽屉”当作一个 Token，也是为了方便演示；真实 Tokenizer 可能把它切成多个 Token。

选最大分数也只是最简单的一种生成策略；实际模型还可以根据概率进行采样。无论用哪种选择方式，第一轮最终选出的 Token 都会成为下一轮前文的一部分。这正是下一节要解释的事情。

四、为什么后面的内容要依赖前面已经生成的内容？

前面，我们看到模型可以从“答：”开始，选择“书桌抽屉”。下一轮，把它加到前文后，可能再选择“。”，于是出现“书桌抽屉。”。

轮次 这一轮已知的前文末尾 本轮选择
第一轮 ……钥匙在哪里？答： 书桌抽屉
第二轮 ……钥匙在哪里？答：书桌抽屉 。

但这只是展示了生成的步骤，还没有回答一个更重要的问题：为什么下一轮不能仍然只看原始问题，而必须把前面生成的文字一起考虑进去？

原因是，GPT 每次预测的并不是“这道题的固定答案”，而是给定当前整段前文，哪个 Token 更适合接在后面。这里的“前文”不只包括用户输入，还包括模型在刚才几轮已经生成的内容。

我们用同一道问题，比较两种可能已经写到一半的回答：

原问题不变，已经生成的回答片段 后面更自然的续写示意
答：钥匙在 书桌抽屉
答：小明去了 厨房，但钥匙仍在书桌抽屉

这两条路径都可以表达同一个故事的信息，但后面适合接什么，取决于前面究竟已经写了什么。第一条接“书桌抽屉”比较自然；第二条如果立刻接“书桌抽屉”，反而会把“小明去了哪里”和“钥匙在哪里”混在一起。

不同前缀会影响下一 Token 的候选倾向；本轮选出的 Token 被追加后，形成下一轮的前缀。候选倾向仅为机制示意，不代表真实模型分数。

表里的“已经生成的回答片段”和“续写”都可能包含多个 Token，这里只是为了让差别在中文里看得出来；它们不是实际模型的候选分数或输出记录。

从模型计算的角度，这个差别是怎么发生的？ 每选出一个新的 Token ID，它就被加入下一轮输入。模型对新前缀形成上下文相关的表示：已有 Token、它们的位置以及 Attention 汇总的信息共同影响最后位置的表示；输出层再根据这个表示，计算新一轮的词表分数。

因此，已生成的内容变化 → 下一轮输入变化 → 上下文表示与候选分数可能变化 → 下一 Token 的选择也可能变化。这里没有在生成过程中重新训练参数；改变的是这次计算所依据的上下文。

反过来假设，我们每一轮都不追加已经选出的 Token，只是拿相同的原始提示反复预测。在模型参数不变、没有额外随机因素、每次都取最高分的情况下，每一轮面对的是同一个输入，得到的也会是同一组分数，进而反复选出同一个 Token。它甚至不知道自己刚才已经写了什么，自然无法把回答接下去。

这也解释了为什么在常规自回归生成中，不能一开始就确定后面所有 Token：在第一轮结果尚未选定时，后面的计算究竟应该沿着哪条前缀继续，还没有确定。理论上可以同时尝试许多候选分支，但选定的那一条实际续写路径，仍取决于之前的选择；这不是 GPU 完全不能并行，而是生成任务本身的条件关系。

所以，GPT 的常规生成循环可以更准确地写成：

用户输入 + 已生成的 Token → 预测并选出下一个 Token → 把它加到已生成内容中 → 继续。

真实生成还会有停止条件，例如生成结束标记、应用设定的长度上限等；出现句号本身不等于模型必然停止。此外，屏幕逐字显示或一次显示一段属于应用的呈现方式，不能据此判断底层 Token 的边界。

现在我们不仅知道了“每次追加一个 Token”，也知道了为什么必须这样追加：否则下一轮就无法根据自己真正写下的内容继续组织回答。

五、那训练为什么可以同时预测很多位置？

既然生成时要先等上一轮结果，训练一整篇文章，难道也要先生成第一个词，再生成第二个词？

区别在于：训练时，整段真实文本已经存在；生成时，未来要写的文本还不知道。

仍然把“书桌抽屉”当成一个教学 Token。假设训练材料已经被切成：

钥匙 / 在 / 书桌抽屉 / 。

同一条数据可以提供三个练习：

当前已知前缀 下一 Token 的训练目标
钥匙 在
钥匙 / 在 书桌抽屉
钥匙 / 在 / 书桌抽屉 。

所有目标都来自同一条已经存在的文本，模型不需要先靠自己预测“在”，才能获得下一道练习的前缀。

但这不等于训练时允许偷看答案。预测“在”的那个位置，不能提前读到后面的“在”或“书桌抽屉”；预测“书桌抽屉”的位置，也不能读取未来的句号。GPT 式模型通常用 Causal Mask（因果遮罩） 在 Attention 中限制每个位置只能读取自己和更早的位置。

这样，训练时多个已知位置的下一 Token 分数可以在一次前向计算里批量得到，再分别与真实目标比较、计算 Loss 并更新参数。这里的并行是指多个位置可一起计算，不意味着 Transformer 各层之间没有顺序依赖。

生成时则没有这些已知的正确后续 Token。第一轮真正选出了什么，才决定第二轮的新前缀。这就是看似矛盾的两种表现背后的同一个原因：已知信息不同，计算依赖也不同。

训练时多个已知位置的目标可以批量计算；生成时下一 Token 尚未知，需要逐步确定。

最小 PyTorch 实验 对照验证了训练目标错位、遮罩阻止未来信息泄漏，以及连续生成时追加新 Token 的过程。实验网络没有经过训练，因此它只验证计算路径，不证明模型的回答能力或泛化能力。

六、现在我们真正理解了什么？

回到小明和钥匙的故事。它是否真的理解了故事、是否具备泛化能力，需要专门的实验回答；本文解释的是回答怎样一步步产生。

一旦要输出回答，GPT 使用的仍是同一个下一 Token 预测过程：利用当前上下文形成数值表示，给整个词表打分，选出一个 Token，把它加到前文，再继续。新文字不是一次性预先写好的；后续预测依赖已经确定的前文。

训练时，整段文本的目标已知，所以多个位置可以在因果约束下并行学习；生成时，接下来要写什么还未知，通常要逐步确定。

这也留下一个工程上的新问题：既然每轮都要利用之前的上下文，新 Token 生成后，模型是否必须重新计算所有旧 Token？哪些已经做过的计算能够复用？

这个问题会引出 Prefill、Decode 与 KV Cache。
